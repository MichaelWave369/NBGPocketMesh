## Concrete gap closed

The preceding E1 work delivered three **independent, read-only consumer implementations** in ThinkTank, PocketBrain and Vessie, each tested against its own hand-written example. That leaves the important question of whether these three receivers accept a **single actual NBGPocketMesh producer output**.

E1-D closes that *format-compatibility testing gap*, not the larger gaps of distributed runtime integration, evidence authenticity, or scientific validity.

## Canonical synthetic packet

The [golden JSON](../tests/fixtures/council-e1-source-golden.json) is generated by `scripts/council-e1-golden.mjs` using the real `evaluateCouncilKeyholes()` and `buildCouncilEvidenceExchange()` functions. It contains a deliberately synthetic scenario:

| Candidate | Ordinary | Rare | Overall |
| --- | ---: | ---: | ---: |
| A | 95/95 | 0/5 | 95/100 |
| B | 90/95 | 5/5 | 95/100 |

E0 reports the pooled-observation equivalence and subgroup distinction. E1 emits one reviewed role receipt each for ThinkTank, PocketBrain and Vessie, all linked to the exact E0 digest. Everything is `SIMULATED`, `PUBLIC_SYNTHETIC`, `authority:NONE`; source identity remains `DECLARED_UNVERIFIED`.

Run:

```sh
node scripts/council-e1-golden.mjs --verify
node --test tests/council-golden.test.mjs
node scripts/council-e1-golden.mjs --stdout
```

`--write` is also available as a **deliberate** regeneration command against the fixed fixture location, but the CI task uses **--verify** so accidental changes fail rather than silently rewrite the record.

## The claim boundary

Passing this CI demonstrates **schema interoperability at exact source revisions**. It does **not** demonstrate that hosted PocketBrain, live ThinkTank, or Windows Vessie can contact PocketMesh; that a user completed a local file import; that source SHAs or model observations are cryptographically attested; or that a scientific hypothesis has been independently confirmed.

Source revision pins are maintained in `scripts/council-e1-golden.mjs` and the workflow checkout steps. Upgrading them requires a reviewed change to both the golden fixture and the workflow, followed by fresh CI. This is intentionally not an auto-updating untrusted dependency.

The JSON can be downloaded manually and opened in PocketBrain and Vessie's respective Council panels. The CI test of their **underlying validators** is not a replacement for physical-browser acceptance of those UI screens.
