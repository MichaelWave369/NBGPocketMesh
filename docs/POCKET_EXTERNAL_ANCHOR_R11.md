# R11 · Independently Queried Policy Anchor

**Status:** executable, **loopback-only reference authority** and one-shot PocketMesh executor for research using synthetic network fixtures. This provides a real *independent process/state* check, **not** a production off-host trust service, TLS-secured remote protocol, hardware monotonic counter, audited key custody, or protection against a hostile administrator of both trust domains.

## Why R11 is different

R10 introduced a **third Ed25519 signer** over the latest R9 policy witness, but an old complete bundle (R8 trust policy, R9 witness, R10 still-valid signed checkpoint and its trust config) could be restored together. Without an independent memory, local verification may accept its own old snapshot.

R11 supplies a **separate operator-maintained authority** whose persistent, create-only epoch history is stored outside the executor's local witness directory. Every execution obtains a **fresh, randomly challenged Ed25519 attestation** from that authority and compares its epoch plus witness digest with the locally validated R10 checkpoint and R9 witness. A newer remote epoch **rejects old local state** even when every restored local signature and hash is individually valid. Conversely, a local epoch ahead of the authority also refuses until an operator promotes the authority.

The reference authority is a **separate process on 127.0.0.1**, with its own directory and **fourth independent Ed25519 key**. This is sufficient to demonstrate the protocol across processes and separate data directories. It is *not actually off-host*: the executor and authority may share the same operating-system identity in CI, and the repo does not configure a remote security domain.

## Trust path

1. **R7**: Permit signer authorizes exactly one reviewed Pocket Album.
2. **R7 PhiID**: A separate approval signer confirms the exact permit purpose, scope and declared subject.
3. **R8/R9**: The operator lifecycle policy refuses retired keys, preserves local attempt journals, and matches a locally witnessed policy history.
4. **R10**: An independent checkpoint key signs the current local R9 witness tip and epoch with a short expiration.
5. **R11**: The executor generates a fresh 128-bit challenge, makes a read-only GET to the **operator-pinned literal-loopback endpoint**, verifies a *fourth*, different Ed25519 public key, challenge nonce, fixed protocol audience, server time/lifetime, and exact epoch+witness digest. It rejects any disagreement, timeout, malformed/oversized response, redirect, revoked signer, or missing authority.
6. Only then does the original signed executor complete its own Keyhole and spend a single-use permit nonce.

The R8 policy-witness preflight is now **asynchronously awaited** at both existing authorization checkpoints, to prevent accidentally running the executor before the remote attestation check completes. This remains subject to unavoidable race windows between checking and execution: R11 is not an atomic distributed transaction or instant revocation mechanism.

### What is signed

The anchor's response is an Ed25519-signed, versioned object with:

- fixed audience: `NBGPocketMesh.externally-anchored-executor.v1`
- exact 128-bit fresh nonce generated by the executor (not chosen by the user input)
- current authority epoch and R9 witness SHA-256
- issue and expiration timestamps, with a maximum lifetime of 15 seconds
- pinned anchor key ID and Ed25519 signature over the exact canonical statement/envelope

The authority returns neither private signer material, OIDC credentials, subjects, raw Pocket Albums, nor output contents.

## Operator setup and commands

In a **local-only research environment**, provision a protected, initially empty directory for the independent authority, a private Ed25519 authority key file outside the worker and repository, and a separate operator-owned R11 client config. These are supplied by the supervisor, never by the client envelope. The reference implementation checks owner-restricted POSIX file modes; it does not audit Windows ACLs.

The authority's **admin interface is CLI only**. There are no HTTP POST/PUT/DELETE promotion routes.

Initialize from the exact already-approved R9 witness tip (manually inspect and supply the SHA-256; no automatic authority trust in a client request):

```sh
POCKET_ANCHOR_ADMIN_CONFIRM=1 node scripts/pocket-anchor-authority.mjs init \
  /authority/independent-state 1 <current-r9-witness-sha256>
```

Start only the explicitly local reference server using a protected Ed25519 private key:

```sh
node scripts/pocket-anchor-authority.mjs serve \
  /authority/independent-state /authority/keys/anchor-private.pem anchor-operator 8787
```

The service listens on **127.0.0.1 only**, accepts only `GET /v1/attest?nonce=<32-hex>`, creates a new time-limited attestation for the latest independent epoch, and has **no mutation endpoints**. The initial response line reports its actual bound port for the supervisor. Do not expose this HTTP service on a public network or through reverse-proxy tunnels: cleartext HTTP is accepted only for a literal loopback address in the prototype.

### Operator-pinned client config

```json
{
  "schema": "NBGPocketMesh.ExternalAnchorClient.v1",
  "endpoint": "http://127.0.0.1:8787/v1/attest",
  "keyId": "anchor-operator",
  "publicKeyPem": "-----BEGIN PUBLIC KEY-----\n...operator-pinned Ed25519 public key...\n-----END PUBLIC KEY-----\n",
  "timeoutMs": 2000,
  "maxAgeMs": 5000
}
```

The endpoint accepts **only** an exact literal IPv4 loopback URL and fixed path. Hostnames, other ports chosen by request JSON, HTTPS remote URLs, redirects, credentials, fragments and existing query strings fail validation. The worker passes a fresh challenge and uses a bounded response (4 KiB) and deadline. There is **no cached or offline fallback** if the authority cannot be reached.

The R11 executor accepts **six supervisor-owned file/directory paths** and the unchanged dual-signature request envelope on bounded stdin:

```sh
node scripts/pocket-anchored-worker.mjs \
  /operator/executor.json /operator/approval-policy.json \
  /operator/lifecycle.json /operator/witness \
  /operator/checkpoint-config.json /operator/anchor-client.json \
  < signed-envelope.json
```

During policy promotion, first approve the R8 policy and its R9 witness epoch, issue a matching R10 signed checkpoint, then **explicitly promote the separate authority** to the exact R9 witness tip:

```sh
POCKET_ANCHOR_ADMIN_CONFIRM=1 node scripts/pocket-anchor-authority.mjs advance \
  /authority/independent-state 2 <new-r9-witness-sha256>
node scripts/pocket-anchor-authority.mjs inspect /authority/independent-state
```

Any interval where local and external epochs disagree **blocks execution**. The authority never accepts arbitrary network-admin promotion requests; only its local operator CLI mutates its epoch state. The opt-in environment variable prevents accidental invocations but is **not authentication**. A real deployment would need OS-level isolation, authenticated change approval and a secure remote administrative plane.

## Reproduce and attack simulation

```sh
npm test
npm run demo:anchor
```

The demo uses ephemeral signing keys, temporary owner-restricted directories, an **independent loopback server** and the actual signed one-shot worker. It:

1. Executes approved synthetic work with the authority at epoch 1.
2. Promotes the R9/R10 local state and the independently held anchor to epoch 2.
3. Demonstrates stale-checkpoint refusal.
4. Restores a **complete old local R8 policy/R9 witness/R10 checkpoint snapshot**, leaving the authority untouched at epoch 2, and demonstrates **REFUSE** before permit nonce consumption.
5. Restores the approved epoch 2 locally, verifies old signing keys are revoked, and permits still-active replacements.
6. Checks R8 local audit records and cleans up only its temporary test data.

The R11 tests additionally cover unavailable authority, forged public key, bad/missing endpoint, unauthorized HTTP method, unchecked promotion, invalid/missing history, key separation, and cross-process one-use replay.

## Precise security boundaries

**Stronger than R10 for a particular rollback scenario:** while the independent authority's live state and signed challenge responses remain trusted, rolling back just the executor's complete local trust bundle does not make it execute a retired key or old policy.

**Still NOT production adversarial rollback protection:** the provided authority runs on localhost, can share the same UID/disk and is not automatically administered outside the executor's threat domain. A sufficiently privileged attacker may edit *both* histories, change pinned public keys, modify program code or manipulate clocks. The local authority state itself uses create-only SHA-256-linked files, not an independently certified monotonic hardware counter or external transparency service. Network transport confidentiality, mutually authenticated TLS, secure remote key custody, authenticated operator identity and independent clock attestation are **not implemented**.

**Not a sandbox or live PhiOS permission:** all demos execute only reviewed, built-in synthetic network status modules under ordinary Node privileges. The previous R7/R8/R9/R10 experimental workers remain in the repository for backward compatibility and cannot be exposed as deployment bypasses. The PhiID development approval is separate from a production human authentication system. No live network device, mailbox, remote inference, or actual OS effect is authorized.

**Next rung:** replace the loopback reference service with a genuinely distinct host and administrative domain, mutually authenticated HTTPS or equivalent secure transport, protected remote signing, durable monotonic storage or audited transparency, and revocation-aware distributed policy under a defined threat model.

**Design principle:** Your local orchestra cannot pretend it is playing the latest approved score when an independently maintained conductor still remembers a newer one.
