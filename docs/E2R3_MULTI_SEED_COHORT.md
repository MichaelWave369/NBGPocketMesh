# E2-R3 · Multi-seed matched-information graph resilience

**Evidence:** public-synthetic / SIMULATED / ANALYZE_ONLY / authority NONE.
**Scope:** an entirely offline cohort benchmark built atop the existing E2-R2 capacity-aware simulator. This does NOT interact with physical networks, network control planes, trained models, authorization, quantum states, optical equipment, or real failure telemetry.

## Why this rung exists

E2-R2's frozen first ledger found that the topology × risk policy led **only one of four** synthetic graph/outage families. The other three were led by risk-only or capacity × risk controls. A single deterministic seed, a single traffic order and weaker single-feature comparators cannot establish a robust advantage.

E2-R3 therefore adds *frozen multi-seed comparisons*, two **matched-information** ablations, paired failure replay, cost-spend auditing and a descriptive **fixture-seed-cluster bootstrap**. It makes no promise that topology will win.

## Fixed inputs and matched-information baselines

Each cohort fixture is generated by the original E2-R2 function for graph A or B with seed:

    seed[i] = uint32(baseSeed + 7919 * i)

Each seed changes synthetic link latency (1–7), capacity (2–9), protection cost (1–4), relative hazard (1–9) and 94 per-vertex fixed-offset synthetic traffic demand magnitudes. The graph edge arrangement itself remains one of the same two 47-node, 188-edge circulants. **Distinct seeds are not independent physical networks.**

The original E2-R2 **topology_risk** policy scores:

    intactExposure(edge) × relativeHazard(edge) / protectionCost(edge)

Here, 'topology' means the flow **path usage determined by graph routing** (and link constraints), not any proven quantum topological invariant. It is not a topological homology algorithm.

Two new frozen policies use the **exact same three accessible inputs** (no held-out failures):

- **matched_additive:** normalize exposure by the maximum intact exposure in the fixture and hazard by 9, then use (normalizedExposure + normalizedHazard) / (2 × protectionCost).
- **matched_harmonic:** same normalized inputs, but score 2 × exposureNorm × hazardNorm / ((exposureNorm + hazardNorm) × protectionCost), or zero if both are zero.

Every policy ranks edges before the trial's failures and uses the same greedy choose-until-cost-ceiling method. Ties resolve with a fixed seeded hash. These are predeclared algebraic alternatives, not optimized using the outcomes.

The existing demand-only, risk-only, capacity × risk, seeded random and zero-budget unprotected E2-R2 controls remain in the results. The unprotected case has zero resource budget and must not be called equal-spend.

## Frozen research experiment

The documented Node demo runs:

- **8 fixture seeds** (baseSeed 369);
- **8 paired attempted-failure trials per fixture seed**;
- both graph types A and B;
- both E2-R2 outage families, whole-mesh risk-weighted and regional risk-weighted;
- 26 attempted failed edges per trial, identical across every method in that trial;
- a protection-cost ceiling of 24 synthetic units.

There are **4 graph × outage families**, with **8 seeded fixtures and 64 paired trial outcomes each**, or 256 unique failure scenarios total. Eight policy results are evaluated on each scenario. Full trial records include the attempted failed edge IDs, all policies' served-demand fractions, the protection lists for each synthetic seed, actual cost spent and a seed-group row.

The existing E2-R2 evaluator uses capacity-constrained, unsplittable shortest-model-delay route placement, in a frozen demand order. The intact demand exposure uses this same evaluation. Nothing is learned or tuned on future failures.

A policy can protect fewer edges because link protection costs differ. **Equal maximum cost ceilings do not guarantee equal exact spend**. E2-R3 computes and reports exact spend per seeded fixture, and flags any violated ceiling or unequal spend rather than silently normalizing away the difference.

## Descriptive uncertainty only

The primary reported metric is mean **fraction of modeled demand served**. For each fixture seed, each policy's paired outage-trial mean is computed first. Comparisons then use the **differences between seed-level means**, expressed in percentage points. This avoids treating eight correlated outage realizations on one fixed synthetic fixture as eight independent topology samples.

For descriptive intervals, a seeded percentile bootstrap draws **fixture-seed clusters with replacement** (400 replicates per contrast) and reports the 2.5th and 97.5th percentiles. This is not a calibrated confidence interval for real networks or a formal significance test. The seed groups are themselves deterministic pseudo-conditions, not independently sampled physical infrastructure.

For each family, report the average served fraction for all eight policies, the highest mean funded policy, topology × risk minus each competitor in percentage points, the descriptive resampled interval, and count of seeded fixtures where topology's average was better/tied/worse.

Never interpret a zero-crossing or non-zero interval as a real-world p-value, hardware proof, quantum result or causal performance advantage.

## Reproducibility and boundaries

From the root:

    npm test
    npm run demo:e2r3

From the React site:

    npm run test --prefix site
    npm run build --prefix site

The frozen CLI prints a concise JSON ledger, includes complete scenario definitions and a SHA-256 digest of the full recomputable trial report. The browser's **Cohort** section can export the full paired trial records locally. Neither uploads files nor consumes live data. SHA-256 here is unsigned and recomputable, **not attestation**.

The E2-R2 behavior remains frozen: E2-R3 adds only two inspection/evaluation exports to its existing module. E2-R1, E2-T, E0 routing, Φ47 receipts, signatures, identity/authorization and trust mechanisms remain unchanged.
